# ADR-002: Mantener SQLite como base de datos del MVP

- **Estado:** Aceptada para el MVP actual.
- **Fecha:** 2026-11-14.
- **Contexto:** GestorTech utiliza SQLite mediante la biblioteca estándar `sqlite3`. El esquema se encuentra en `app/infrastructure/schema.sql`; la conexión, inicialización y cierre se gestionan en `app/infrastructure/database.py`. La aplicación permite configurar la ruta mediante `GESTORTECH_DATABASE`. En la ejecución con Docker Compose, el archivo se conserva en un volumen persistente. La entrega actual requiere una aplicación local reproducible y no documenta una necesidad operativa que obligue a disponer de un servidor de base de datos independiente.
- **Decisión:** Mantener SQLite para el MVP y para la entrega actual. No realizar la migración de motor como parte de esta decisión. La aplicación seguirá utilizando el archivo SQLite configurado y la persistencia del volumen cuando se ejecute mediante Docker Compose.
- **Alternativas consideradas:**
  1. **PostgreSQL:** base de datos cliente-servidor con capacidades adecuadas para concurrencia, despliegues compartidos y crecimiento. Se considera una alternativa válida si GestorTech requiere operación multiusuario más concurrente, despliegue distribuido o mayores necesidades de administración.
  2. **MySQL:** otra alternativa cliente-servidor que puede satisfacer escenarios de operación compartida y despliegue. Su conveniencia deberá compararse con PostgreSQL según compatibilidad, operación, costos y plataforma elegida.
- **Consecuencias positivas:**
  - No se necesita administrar un servicio de base de datos independiente para ejecutar el MVP local.
  - La configuración es sencilla y reproducible en el entorno actual.
  - Se conserva el esquema, el código de persistencia y las pruebas existentes sin introducir una migración de datos dentro de la entrega inmediata.
  - Docker Compose conserva el archivo de base de datos mediante el volumen `gestortech_data`.
- **Costos y limitaciones:**
  - SQLite no ofrece el mismo modelo de concurrencia de escritura ni las mismas opciones de operación multiinstancia que una base de datos cliente-servidor.
  - El archivo de datos requiere una estrategia de respaldo, restauración y persistencia adecuada para el entorno donde se ejecute.
  - Si aumentan la concurrencia, la disponibilidad requerida o las necesidades de operación compartida, será necesario reconsiderar esta decisión.
- **Evolución pendiente:** el [issue #20 – Evaluar y migrar la persistencia de SQLite a PostgreSQL o MySQL](https://github.com/LzMauLz/Proyecto-GestorT/issues/20) registra la comparación y posible migración como prioridad Should. Antes de cambiar el motor se deberán documentar la alternativa seleccionada, el plan de migración, la integridad de los datos, las pruebas y la reversión. El issue no significa que la migración ya esté aprobada ni ejecutada.
- **Referencias de implementación:** `app/infrastructure/database.py`, `app/infrastructure/schema.sql`, `config/settings.py`, `app/__init__.py` y `docker-compose.yml`.
